# HardLinkRemover

HardLinkRemover is a Windows utility for enumerating and deleting hard links. Version 2 provides both a command-line program and a native Win32 GUI. It uses the Windows hard-link APIs directly and does not launch or parse `fsutil`.

## Features

- Lists every directory entry that points to the same file.
- Separates every CLI hard-link group with a numbered visual boundary while keeping path indices globally continuous during interactive selection.
- Deletes exactly one or more explicitly supplied link paths.
- Provides an interactive CLI selection such as `1,3-5`.
- Retains an explicit `delete-all` operation for removing a complete hard-link group.
- Provides a native tree-grouped GUI with file/folder drag-and-drop, recursive folder scanning, checkboxes, refresh, and multi-selection deletion.
- Handles Unicode paths and rejects directories, reparse points, and ordinary single-link files in precise-delete operations.

## Build

Requirements:

- Windows
- CMake 3.20 or later
- A C++17 compiler, such as Visual Studio 2022 with the Desktop C++ workload

Enter the HardLinkRemover project directory and build it independently:

```powershell
cd HardlinkRemover
cmake -S . -B build -DBUILD_TESTING=OFF
cmake --build build --config Release --parallel
```

With the Visual Studio generator, the executables are created at:

```text
build/Release/HardLinkRemover.exe
build/Release/HardLinkRemoverGUI.exe
```

Useful CMake options:

```powershell
# Do not build the GUI
cmake -S . -B build -DHARDLINKREMOVER_BUILD_GUI=OFF

# Build and run tests in a separate directory
cmake -S . -B build-tests -DBUILD_TESTING=ON
cmake --build build-tests --config Debug --parallel
ctest --test-dir build-tests -C Debug --output-on-failure
```

Test programs are not generated by default. When tests are explicitly enabled, their binaries are placed in the separate `build-tests/tests/<configuration>` directory rather than the Release output directory.

## Command line

```text
HardLinkRemover list <file> [file ...]
HardLinkRemover delete [--yes] <link> [link ...]
HardLinkRemover delete-all [--yes] <file> [file ...]
HardLinkRemover select <file> [file ...]
HardLinkRemover <file> [file ...]
```

Examples:

```powershell
# Inspect a hard-link group
HardLinkRemover list "C:\data\source.bin"

# Delete exactly two named links
HardLinkRemover delete "C:\data\copy-a.bin" "C:\archive\copy-b.bin"

# Enumerate links and choose indices interactively
HardLinkRemover select "C:\data\source.bin"

# Explicitly delete every name of the supplied file
HardLinkRemover delete-all "C:\data\source.bin"
```

Passing file paths without a command is equivalent to `select`, which also preserves the original drag-files-onto-the-CLI workflow. Add `--yes` or `-y` to `delete` and `delete-all` to skip the final confirmation. As required by Windows, all names in one hard-link group reside on the same volume.

The CLI automatically selects Chinese or English from the current Windows user interface language. Chinese environments receive localized help, prompts, and results; all other environments use English. Command names and options remain unchanged, and output is encoded as UTF-8.

## GUI

Run `HardLinkRemoverGUI.exe` and click **添加文件或文件夹** to open one unified picker that can select files, folders, or a mixture of both. You can also drag files and folders directly into the window. The picker follows native Explorer selection behavior: hold Ctrl or Shift for multiple selection, and show item check boxes only when the current user enabled them in Explorer. Selected folders are scanned recursively. Each hard-link group is shown as an expandable root node and its link paths are shown as child nodes. Check individual child paths, or check a group node to select the complete group, then choose **删除已勾选**. **移出列表** only hides checked paths or the current node and never deletes disk files. Right-click tree nodes for group selection, list removal, path copying, deletion, and refresh actions.

## Safety model

Before deleting, the core validates all supplied paths. It refuses directories, symbolic links and other reparse points, and files that currently have only one directory entry. Validation is completed before any selected path is removed, so intentionally selecting every name of a hard-linked file remains possible.

Deleting every name of a file permanently deletes its data. Both the CLI and GUI show a warning before this operation unless confirmation is explicitly disabled with `--yes`.
